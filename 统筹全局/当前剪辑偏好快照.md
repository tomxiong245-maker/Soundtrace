## v15-draft 变更（相对 v14-draft）

### D6 · 句中保护（sentence_position_gate）

**证据**：round 2 N003 mentor reject "不要剪（要保证完整性，这个是在句中）"；R-S038 mentor "为什么要剪"（虽 crossfade 修好仍 reject）。mentor 明确优先级：**完整性 > 剪口癖**。

**动作**：任何候选（filler_hesitation / filler_weak / immediate_repetition）如果 `clause_position` 落在 `clause-mid` 或 `cross-clause`，**默认不提名**。仅 `clause-boundary` / `clause-head` / `clause-tail` 才进候选池。EP04 用 codex `semantic-transcript-v1` 的 clauses 数据；EP03 无 codex 输出，退回 gap 启发式（`prev_gap` 与 `next_gap` 都 >0.4s 才视为 boundary/head/tail）。

**保守缺省**：位置未知（`no-track-sem`, `no-clause`, `edge-of-track`）→ 默认保留，不提名。

### D7 · immediate_repetition 收紧

**证据**：round 2 R-S038 "报告报告" 与 R-E306 "一个/一个" mentor 均 reject 且 feedback 说"其实可以不用剪"。v14 的单纯 "2-4 字相同 phrase, gap<0.3s" 阈值误报太多。

**动作**：v15 加 stutter signature 门槛，满足以下任一才提名：
- 两次出现的时长比 ≥ 1.3（真 stutter 有节奏差）
- OR 中间 gap < 0.15s（极紧凑重复，暗示 self-correction）
- OR 前后 ±1s 内出现犹豫标志（呃/额/嗯/uh/um）

其他条件不变（2-4 字，gap ≤ 0.3s）。

### rendering_gate 默认升到 80ms

**证据**：round 2 R-S032 accept（50ms 可以）但 R-E306 / M001 / N002 仍 reject "剪辑痕迹明显"。80ms 是稳妥基线，120ms + tanh 为兜底。

**证据**：EP04-review-mixed-14 中 S025 / S081 / S082 全部 mentor reject，feedback = "没有咳嗽" / "根本没有" / "声音很轻"。样本 100% 误报。

### D2 · filler_hesitation 词内过滤（对应 OPT-016）

**证据**：EP03 中 "额" 被匹配为犹豫词，实际是 "额度" 首字。E301/E303 mentor 明确 reject "额度是一个词"。E302 "er" 是 ASR 误识别，reject "一个完整的单词"。

**动作**：`strong_tokens` 增加 `next_char_blocklist` 字典（v14 起生效）：

```json
"strong_next_char_blocklist": {
  "额": ["度", "外", "头", "定", "角", "上", "面"],
  "唔": [],
  "哦": ["豁"],
  "呃": []
}
```

匹配规则：当 filler token 命中且**后一个 token 首字**落在 blocklist 时，不生成候选。

英文 filler（`er / erm / um / uh`）追加约束：**上下文必须至少一半以上是中文 token**，否则视为 ASR 误识别，不生成候选。

### D3 · rendering-quality gate（对应 OPT-017）

**证据**：4/14 mentor feedback 明确指出"剪辑痕迹明显"（S038 / S032 / E304 / E306）。原因：本轮预听为 butt-splice。

**动作**：所有 proposed-cut 预听和最终 EDL 渲染必须走 crossfade gate：

```yaml
candidate_rendering_gate:
  min_crossfade_ms: 50          # 已达到（equal-power sin/cos）
  preferred_crossfade_ms: 80    # 下版目标
  fallback_crossfade_ms: 120    # click 未消除时的兜底
  curve: equal_power_sin_cos    # 默认；备用 tanh S-curve
  ab_required_when: "候选不在 autocut_policy 白名单中"
```

**待验证**：50ms 是否足够 → mentor 复听 S038 / S032 / E304 / E306 判断是否撤销"剪辑痕迹明显"评价。

### D4 · "对/然后/这个"歧义分层（对应 OPT-018）

**证据**：E305 "对这个" mentor reject "不是口癖啊，是完整的词"。E304 "然后这个" mentor accept。差异：语境。

**动作**：把 `weak_tokens` 拆到两个子字典，规则改为：

```json
"weak_backchannel_tokens": ["嗯", "嗯嗯", "嗯对", "哦"],
"weak_topic_connective_tokens": ["对", "然后", "这个", "那个"],
"weak_filler_tokens": ["啊", "就是", "那個", "這個", "然後", "對", "就是說"],
"weak_topic_connective_next_token_rule": "仅当后一 token 也在 weak_filler_tokens 或 weak_backchannel_tokens 中，才提名；否则默认保留（视为话题连接语）"
```

### D5 · long_pause / immediate_repetition / filler_immediate_repetition

**证据**：
- long_pause：S022 (0.71s) accept、S047 (6.58s) accept、S032 (0.61s) reject（reject 因剪辑痕迹）→ **时长阈值本身有效**

**动作**：v14 **保留 v12** 的 long_pause / immediate_repetition / filler_immediate_repetition 阈值不变。仅新增 D3 rendering gate。

## 已收集的偏好

### 1. 不改变语义的音频处理偏好

| 方面 | 当前偏好 | Agent 可如何使用 | 不能据此做什么 |
| --- | --- | --- | --- |
| 输入源 | 对齐的原始 mono WAV 只作为只读输入；普通新 run 必须先生成 DeepFilterNet 派生轨，并用该派生轨做分析、审核试听和渲染 | 写入 `plan.json` / `processing_manifest.json`，校验原始与派生 SHA、sample timeline 和 30 ms 尾段回填 | 不得从 raw 绕过 DeepFilterNet，也不得把多个处理链层层叠加到最终母带 |
| 拼接 | 语音剪口用 equal-power（sin/cos）；建议 `crossfade_ms = min(200, cut_ms / 2)`，且不得超过相邻较短可用片段的 50% | 对已经获准的剪口生成渲染参数 | 不把 crossfade 自然当作该剪口内容正确 |
| 极短 ASR 词 | 时长 `< 0.10 s` 的词级口癖命中通常是时间戳粘连噪声 | 不把它们列为可剪的词表候选；写明过滤原因 | 不适用于咳嗽、爆音等声学事件，也不证明整段无内容 |
| 响度 | v12 试用了两遍 `loudnorm`，工作目标为 `I=-16 LUFS / TP=-1 dBTP / LRA=11` | 产出客观 QC 报告，并把实际测量与目标并列 | 不把一次测量或目标值称为 Mentor 已冻结的发布规格 |

v12 的实际测量为输出约 `-16.5 LUFS / -1.0 dBTP`。它证明两遍归一化链路曾真实运行，不证明发布响度、动态范围或编码规格已获批准。

### 2. 口癖候选偏好

下列规则的结果一律是“提名候选”或“排序更靠前”，不是裸 `accept`：

| 类别 | 当前偏好 | 风险与处理方式 |
| --- | --- | --- |
| 强口癖 | `呃 / 额 / 唔 / 唉 / 哎 / 哦 / uh / um / er / erm` 可作为低风险候选 | 仍须通过跨轨安全门；本期先做代表性人工校准，再只把合格预测写为 `machine_proposed_*` |
| `嗯` | 保留活人感；只在单个时长 `≥0.8 s`，或同一轨 5 秒内 `≥3` 个时提名 | 其余“嗯”默认保留；不要因为字面命中批量删除 |
| 弱口癖 | `啊 / 那个 / 这个 / 就是 / 然后 / 对`，并覆盖 `那個 / 這個 / 然後 / 對 / 就是說 / 这据 / 這据 / 這據` | 仅在 `0.10–0.40 s` 的短促命中时提名；同轨 5 秒最多 2 个，紧邻同字（gap `<0.3 s`）保留最后一个 |
| 跨轨保护 | 其他轨为 primary、文字冲突、重叠或归属不明时，不把本轨候选升级为全局删口 | 标为 `BLOCKED` / `human_review_required`；source-track gate 也要独立标注 |

### 3. 长停顿与其他高风险候选

以下参数只能帮助 Agent 找到、排序和做 A/B，不能直接写入任何 EDL：

- 长停顿候选：所有轨同时无词级活动且逐轨声学安静时，才可用 `silencedetect noise=-30dBFS:d=0.5`、`trigger_seconds=0.6`、边界内缩 `50 ms` 提名。
- 如真人决定压缩，当前的**试听建议**是按原停顿长度保留自然呼吸：`0.6–1 s → 100/100 ms`、`1–2 s → 200/200 ms`、`2–3 s → 300/300 ms`、`≥3 s → 400/400 ms`（头/尾）。
- 长停顿必须由真人听原版和压缩版 A/B 后作出 `human_accept / human_reject`。它不能因 v12 曾批量渲染而降级为低风险。
- 咳嗽、碰麦、爆音、串音/混音不明、说错重来、整句语义重复和离题全部保持高风险：Agent 只生成候选与试听，不自动剪、不自动 gate。

### 4. 音乐与响度的两个层次

- **已固定的素材**：`音频参考库/raw material/第三集/片头片尾music.mp3`，SHA-256 为 `3f3a7150c43c21fe5709a8a7b7152590a77579bd4ce87d3ad0e15ed1bb81ed83`。素材不匹配时必须 `BLOCKED`，不得换歌。
- **当前正式时序基线**：`reference-linear-v1`（片头 0–5 秒纯音乐、5–约16 秒语音进入并淡出；片尾语音结束前 22 秒淡入、结束后约 37.976 秒尾乐）。
- **EP04-v12 试听候选**：15 秒片头、3 秒 equal-power 交叉进入语音；结尾 3 秒交叉进入、15 秒尾乐且最后 3 秒淡出。它反映最新偏好，**但尚未替换** `reference-linear-v1`。

下一次最终 QC 必须明确记录选择了哪个 `music_template_id`。在这之前，Agent 可以为对比试听分别渲染，但不得私自把 v12 的 15 秒结构升级成发布模板或把目标响度称为最终规格。

## 后续 Agent 的使用方式

1. 在 `plan.json` 写入 `preference_profile_id`、本文件 SHA 和选择的 `music_template_id`；这三个字段与 `autocut_policy` 分开。
2. 用本快照生成/排序 `all_candidates.json`，并在每条候选写 `preference_profile_id` 与触发规则；候选不改音频。
3. 将所有高风险候选送入人工审核；低风险口癖/紧邻重复按 F05 做分层代表抽样。样本不足或意见不稳定时，升级全审。
4. 机器只可对未人工决定、通过安全门的低风险候选写 `machine_proposed_accept / machine_proposed_reject`；高风险永远写 `human_review_required`。
5. 渲染时在 `preference_application_report.json` 列出：采用了哪些候选/渲染偏好、哪些因安全门被阻断、音乐模板是否仍为试听候选、以及任何与本快照不同的参数。
6. 最终人听审后，才把本期的返工结果写成 `experience_proposal.json`。跨期更新本快照仍需冻结 benchmark、独立复核和人工晋升；不能在线改 Champion 或 `autocut_policy`。

## 不允许的误读

- “v12 一次跑出了很多剪口” ≠ 这些剪口已经由真人批准。
- “机器从代表样本学到了阈值” ≠ 长停顿、瞬态、串音、语义重复等高风险可以自动外推。
- “输出接近 -16 LUFS / -1 dBTP” ≠ 可以称为发布成片。
- “固定音乐素材” ≠ Agent 可以自行决定新的片头片尾时序、音乐增益或 ducking。
