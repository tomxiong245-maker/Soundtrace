# F02 降噪与时间线校准

## 功能目的

降低持续噪声，同时保证处理后的内容时间线与原始音频一致；任何滤镜延迟必须实测、绑定版本并补偿。

流程位置：`同步决定 → 降噪 → ASR`。

## 输入与输出

输入：已通过 F01 的 N 轨 WAV、降噪工具与参数版本；每条轨必须分别处理并继续保持共同时间线。

输出：等长处理轨、校准报告、参数/工具版本、输入输出 SHA、A/B 试听和时间线 manifest。

## 当前状态

### 已验证事实

- 历史 `afftdn` 曾在 EP03 使用，固定延迟为 1200 samples / 25 ms；它仅保留为历史 run 的可复现证据，不再是生产工具、回退选项或 Tool 注册表条目。
- 项目负责人已明确选择 DeepFilterNet，现已**直接替代**原有降噪方案。所有普通 `start` run 都固定使用官方 `v0.5.6` arm64 CLI（本地 SHA-256 `4601e7f4e4c03e59a4c5b5000216ef3add3e808799cfccd95e14e83ea4611081`），调用 `--compensate-delay --atten-lim-db 12`；原始 WAV 不改写，也没有 `--denoise-backend raw` 生产开关。
- 该官方二进制在 48 kHz 合成 WAV 的 1 / 3 / 7 秒试验中均比输入少 1,440 samples（30 ms）。项目适配层已将它接入新 run：先临时转成 PCM16 供 CLI 使用，再将处理结果和**原始末尾 1,440 samples**拼接回同长轨。双轨 24-bit 合成输入实际验证为 96,000 → 96,000 samples；orchestrator 的双 EDL 和双渲染都实际使用 `denoise/*.deepfiltered.wav`，而非 raw。
- 已用 EP04 三条真实原始轨生成两段 30 秒试听（60–90 秒正常对话、2418–2448 秒长停顿）。每段 3 条输入和 3 条输出均为 `1,440,000` samples，DeepFilterNet 原始短输出均为 `1,438,560` samples，随后回填 1,440 samples；4 个试听 MP3 均可完整解码。试听位置为 `main/runs/EP04/EP04-deepfilternet-listening-20260813-190500/`。

## 安全边界

- 历史 25 ms `afftdn` 记录不能用于当前或未来 run。
- 工具、版本或参数改变必须重新校准。
- 处理轨必须与原始轨等长；无法证明时间线安全则不得进入候选和 EDL。
- DeepFilterNet 的 30 ms 末尾采用“原始尾段回填”而不是静音补齐；此设计只解决整数 sample 时间线，不能代替真人听感判断。工具版本、CLI SHA、补偿方式或参数任一变化，必须重新测量。
- 客观噪声指标不能代替真人听感。

## 验收标准

- 多窗口延迟估计稳定且补偿后在门限内；
- 时长、采样率和样本数满足契约；
- A/B 由真人盲听，记录噪声改善与语音损伤；
- 新工具在短片段通过延迟、内存、许可证和数据流门禁后才能进入整期实验。
