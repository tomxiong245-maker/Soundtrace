
# F04 候选生成、风险分层与跨轨安全

## 功能目的

从文字、停顿、重复、口癖、说错重来、串音和声学事件中找出“值得处理或值得真人看”的候选；先保证不会误伤其他轨正在讲话的内容，再按风险把少量最重要的候选交给人审。

流程位置：

~~~text
ASR / VAD / activity / 音频事件
→ 全量候选冻结
→ 跨轨安全与风险分层
→ 高风险全审 + 低风险代表性抽样
→ 人审 / 机器辅助预测
~~~

## 候选不是剪口

每条候选必须有：

- 整数 sample 开始/结束、来源轨和是否为全局时间线剪口；
- 拟删文本/声学事件、前后上下文、reason_family、reason_key、证据词或声学特征；
- cross-track 结果、风险等级、阻断理由、候选规则版本和输入 SHA；
- 机器预测时的阈值、校准报告和 policy provenance。

候选生成只能建议，不能直接改音频或写成 human_accept。

## 风险分层

### 高风险：全量人审

- 长停顿压缩；
- 说错重来、远距离/整句语义重复、离题；
- 咳嗽、碰麦、爆音、音乐干扰；
- 串音/主讲归属不确定、说话人切换、重叠；
- 数字、专名、否定、结论、敏感表达；
- 其他轨有不同文字、跨轨安全 BLOCKED 或 ambiguous；
- 删除长度超出当前低风险政策的任一候选。

### 低风险：代表性审核后再预测

连续、紧邻、规则明确的重复口癖等候选可分层抽样。抽样规则与审批门见 F05：每层至少 3 个、10% 上限 10、纳入阈值边界、固定随机种子；样本不足或意见不稳定则升级全部人审。

低风险也只能得到 machine_proposed_accept / machine_proposed_reject。没有有效 autocut_policy 时，
预测不会进入 human_approved EDL；通过安全门、校准充分的低风险 machine_proposed_accept
会进入 machine_assisted_draft 供整片试听。高风险未审项始终为 human_review_required，
不会因为有低风险代表样本就被机器外推为可剪。

## 跨轨与声学安全

- 全局语义删除必须检查全部语音轨；一条轨静音不等于节目可以删。
- source 轨没有主讲话、其他轨有主讲话、关键重叠、不同文字或身份不确定时，阻断全局删除并升级人工。
- 长停顿只能由所有物理轨同时无词级活动、且每轨声学安静的区间提名；任一轨有声音、咳嗽、碰麦或音乐即阻断。
- 弱口癖连续重复时保留最后一个词，只提出前面的重复；单个“对/然后/就是/这个/那个/啊”不应仅因字面出现就删。
- 串音 gate 若只改变单一来源轨的电平或屏蔽，它必须单独记录为 source_track_gate，绝不能伪装成全轨时间线删剪。

## 当前剪辑偏好如何参与候选

`统筹全局/当前剪辑偏好快照.md` 的 `editing-preference-profile-v15-draft` 可用于提名和排序，
但不能改变本节的风险分层：

- 强口癖、经护栏过滤的短弱口癖和紧邻重复可作为低风险候选；仍要通过跨轨安全与 F05 的代表性校准。
- “嗯”默认保留，只有较长或密集出现时才提名；弱口癖只在 `0.10–0.40 s`、同轨 5 秒不超过 2 个、紧邻同字保留最后一个的条件下提名，并覆盖简繁体/常见 ASR 别名。
- `silencedetect -30 dBFS × 0.5 s`、`trigger=0.6 s`、`50 ms` 边界内缩和分档保留呼吸只能生成长停顿 A/B 候选。长停顿仍是高风险全审。
- 咳嗽/碰麦、串音、重叠、说错重来、语义重复和离题即使有 v12 实验参数也仍是高风险候选；不能因它们在一次实验渲染中被处理，就降级为低风险。

候选与 `all_candidates.json` 必须写入 `preference_profile_id` 和触发的偏好规则；任何过滤、阻断或升级理由都必须可追溯。

### 生产基线与当前审核包

普通 `delivery_orchestrator.py start` 默认冻结 `filler-global-pause-v18` 到本期
`frozen/candidate_rules.json`，并把其 SHA 写入 `run_identity.json`、`plan.json` 和
`all_candidates.json`。当前 `EP04-label-loop-v1-20260815-1805` 是一次显式冻结
`filler-global-pause-v18` 的审核运行；它的准确规则版本只以 CURRENT_DELIVERY_FACTS、该 run 的
`plan.json` 与 `frozen/candidate_rules.json` 为准。两者都不是 Champion 升级，也不改变
`autocut_policy = NOT_APPROVED`。

- acknowledgement 型“嗯”在没有可靠说话人归属时一律默认保留，不因时长或密集程度提名；不会把中间夹着实词的多个“嗯”拼成一刀。
- 弱口语词只提名短促的连续同词：每个命中必须为 0.10–0.40 秒、相邻间隔小于 0.3 秒，并保留连续串的最后一个。完整句子里的单个“啊/那个/这个/就是/然后/对”默认不动；`filler_hesitation` 位于 clause-mid、cross-clause 或语义未知时也默认保护。
- 紧邻完全重复的内容词可独立提名，即使位于分句中间；只提议删去第一次、保留第二次，仍必须通过跨轨安全和真人审核。普通或对他人的认可型“嗯”不属于这个候选家族。
- 长停顿仍要求全轨无词级活动和逐轨声学安静。0.6 秒只是分析/诊断提示；为避免把审核包淹没，当前只有至少 1.5 秒的共同安静进入审核候选。A/B 只压缩中段：按原停顿长度留下头尾各 100 / 200 / 300 / 400 ms 的自然呼吸，不会删成零停顿。
- `--review-budget 20` 是当前一期的人工容量目标：高风险先全部入包；若高风险本身超过 20，入口必须停止并报告，不能漏审或机器代决。剩余容量不足以形成有效代表样本的低风险层会保持未剪、写为 `human_review_required`。

上述规则旨在减少“剪得太多、听起来不自然”，而不是让机器有权删完整句子或高风险内容。V16 仍只覆盖口癖、紧邻重复与全轨长停顿；说错重来、语义重复、离题、串音、咳嗽/碰麦等需要各自的候选模块和同一审核门。

## 事件级去重与已审路由（2026-08-16）

候选 ID 不是事件身份。候选生成后必须先计算稳定的 `event_key`（输入/轨道身份、归一化匹配文本、时间重叠窗口、候选家族），再与历史人审事件账本匹配：

| 路由 | 条件 | 下一步 |
| --- | --- | --- |
| `already_reviewed_exact` | 同一事件且边界未变 | 显示历史决定/备注作参考；不复制为本轮 human decision、EDL 或自动剪辑权限 |
| `semantic_reuse_boundary_review` | 同一事件但边界有变化 | 显示旧语义证据；新增执行/边界复核，不能继承旧试听批准 |
| `rejected_false_positive` | 历史 reject 归类为 ASR 错误或误报 | 形成抑制候选的 Challenger 证据；未晋升前仍不能静默隐藏当前候选 |
| `rejected_execution_issue` | 历史 reject 是音量、crossfade 或剪辑痕迹 | 不抑制语义候选，生成执行修复任务 |
| `new_event` | 无可靠历史匹配 | 按风险分层进入本轮审核 |

匹配必须保留 `matched_case_id`、原始/新边界、文本归一版本、匹配分数和理由。事件路由目前是审核提示与未来排序依据，不是“代替真人确认”的机制；任何本轮 `human_accept`、EDL 或自动剪辑授权仍必须由本轮明确人审或以后经人工晋升的政策产生。

## 安全边界

- 规则 confidence 不是校准概率；不准假装为“学习分数”。
- 没有明确人审或有效政策的机器结论不能叫 accept。
- Champion 不得因单期候选或一个 run 的标签自动改变。
- 无候选区域必须抽查，不能只用“没有触发候选”证明内容干净。

## 验收标准

- 所有候选可回到输入、规则、证据与全轨上下文；
- 跨轨危险 fixture 和音乐/声学干扰 fixture 全部 fail closed；
- 每类候选有清晰的人审/抽样/自动政策归属；
- 在冻结 benchmark 上测量 precision、recall、false-safe、false-block；
- 新规则先在 Challenger 与 Champion 对比，经独立复核和人工晋升后才进入稳定生产。

## 边界精修与剪口质量预测（2026-08-15 加入生产入口）

上下文：EP04 v20 mentor 熊镇正对 C026/C028 reject 备注"剪辑的时候声音明显小了 / 剪辑痕迹很重"；累计 65 条历史决定里 8+ 条 reject 都带类似 feedback。溯源发现 ASR 词级时间戳误差 20–50 ms，直接剪会残留前一个词的尾音，加上 100 ms crossfade 混叠听起来像"又回去 又回去"。

### 已接入普通 `start` 流程的两个新 stage

`main/orchestrator/delivery_orchestrator.py::build_candidates_and_review` 在 `candidate_generation` 之后依次调用：

1. **`snap_candidate_boundaries`** — 每条候选的 `start_sample / end_sample` 在 ±150 ms 内扫 20 ms 窗口找能量最低点，再在 ±5 ms 内找零交叉点，把边界移过去。原边界保留在 `start_sample_original / end_sample_original`；新边界写回 `all_candidates.json` 与 `calibration_source.json`（下游 preview 用新边界，A/B 与最终成片一致）。EP04 v23b 实测 12/12 候选全部精修、平均边界移动 204 ms。
2. **`predict_cut_artifact`** — 基于边界处 RMS（转 dBFS）、时长、`clause_position`、候选家族综合打分 `artifact_risk_score`（0-1）；输出 verdict ∈ `{OK, HUMAN_REVIEW, BLOCK}`。verdict 与依据写进 `all_candidates.json` 的 `artifact_risk` 字段，前端 mvp.html 在候选卡上以颜色标签 + 折叠面板显示。

### 边界陷阱清单（学自 8 条"剪辑痕迹" reject）

- **边界处 RMS > -25 dBFS**：直接切在语音上 → 剪辑痕迹重（+0.7 score）
- **边界处 RMS ∈ [-35, -25] dBFS**：语音尾音未消完 → 剪口可能咔哒（+0.5）
- **边界处 RMS ∈ [-50, -35] dBFS**：过渡区 → 需 crossfade 掩饰（+0.2）
- **边界处 RMS < -50 dBFS**：静音区 → 剪口干净（0）
- **时长 300–700 ms**：历史 8/10 剪辑痕迹 reject 集中在此区间 → +0.15
- **`clause_position ∈ {clause-mid, cross-clause, edge-of-track}`**：+0.15
- **`filler_immediate_repetition / cough_like / mic_bump_like` 家族**：直接 BLOCK（历史全 reject）
- **`REAUDIT_*` 家族**：BLOCK（永久登记的边界样本）

## Agent 读取与正式学习闭环（2026-08-16）

Agent 必须读取最新的案例/政策卡，但不得因为一次新 feedback 就直接改本节阈值、`P-XX` 说明或生产候选规则。旧 `editing-experience-distiller` 输出可用于只读分析和人类复核；正式学习入口是：

1. 只读取逐项 `human_decisions` 与 `feedback`，排除 bulk accept、机器预测和空白草稿；
2. 运行 `main/orchestrator/build_label_learning_challenger.py` 生成新的独立证据包；
3. 先做事件级去重，再归类 `asr_error / semantic_keep / semantic_cut / execution_issue / false_positive / unknown`；
4. 输出版本化政策卡（条件、案例、反例、状态、回滚信息），初始仅为 `candidate` 或 `challenger`；
5. 只有历史回归、独立样本和人工晋升都通过后，才可把一张卡转为对 `machine_assisted_draft` 的受限影响。

`LABEL-LEARNING-v3-20260816` 已跑出该证据链；v2 仅留作重复计数/manifest 问题的历史诊断。当前 active review 有草稿，故不补写路由侧车；下一次新 run 才通过 `start --event-history-run` 生成 `event_routes.json`。学习产物始终是可读 Markdown/JSON，不是黑盒模型或隐式自动删剪。

### 活跃生产保护规则（2026-08-16）

未来新 run 会额外冻结 `main/orchestrator/editing_policy.guards-v1.json`，并在候选冻结后写 `policy_application.json`。它将每项候选路由为下列之一：

- `auto_preserve`：仅用于已有精确反例的完整词/词边界误报，或完整分句内不应由字面形状删掉的弱口语词；候选留在全量证据里，但不进入审核包、机器预测或任一 EDL；
- `human_review_required`：长停顿、说错重来、语义重复、离题、串音、咳嗽/碰麦等高风险家族，或没有犹豫特征的紧邻重复；
- `machine_calibration_eligible`：仍按本期风险、跨轨安全和代表性校准走既有流程。

该层只有“保护或升级”两种自动动作。`autocut_policy` 仍为 `NOT_APPROVED`，所以它绝不会创建 `auto_cut_eligible`、EDL 动作、机器删除或真人决定。当前有草稿的 label-loop 不追补这层；它从下一次新 run 才生效。
