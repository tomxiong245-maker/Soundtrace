# F08 外部知识、内部经验与监督学习

## 功能目的

让系统随着公开方法和多期真实审核数据持续改进，同时保证学习过程可解释、可评测、可回滚，不污染生产。

## 两条学习线

### 外部知识线

视频、官方文档和公开资料被提取为知识卡，记录来源、证据等级、适用范围、风险、状态和版本。它是“教材/先验”，不是某一期的直接删除指令，也不是监督学习标签。

### 内部经验线

每期保存完整候选集合、真人 human_accept/human_reject、机器 prediction manifest、双 EDL、处理参数、QC、听感、工具版本和 SHA。未来如恢复 adjust，再补调整后 sample 边界。它以后可用于改规则、检索案例、校准候选排序或训练候选排序器。

## 当前状态

### 2026-08-16 批准的内部经验闭环

当前“学习”仍不是在线监督训练。它是一个可解释、可回滚的 Challenger 管线：

```text
human_decisions + feedback
→ event ledger 去重/继承
→ feedback classification
→ policy card（条件/行动/案例/反例/状态）
→ 历史回归 + 独立 benchmark
→ 人工复核/晋升
→ 仅在 machine_assisted_draft 中试用
```

事件账本防止边界精修或候选 ID 变化造成重复标签；反馈归类把 ASR 错误、语义保留、语义可剪、执行问题、误报和未知分开；政策卡必须保存 `source_case_ids`、版本、状态、适用范围、反例和回滚信息。已审语义决定可以继承，但新边界的自然度必须单独复核。

当前只允许输出人可读的 Markdown/JSON 经验产物，不训练黑盒模型、不在线改规则、不生成真人决定。历史 bulk accept、机器预测和空白草稿不进入真人经验库；`autocut_policy` 继续为 `NOT_APPROVED`。

### 当前实际证据（2026-08-16）

`main/runs/LABEL-LEARNING-v2-20260816/` 因 27 个 canonical case 的跨来源重复计数、以及后来 manifest 不完整，只保留为历史诊断。当前有效证据包是 `main/runs/LABEL-LEARNING-v3-20260816/`：它只读取历史人审元数据，生成 65 条独立逻辑事件（24 accept / 41 reject）、37 条 quarantine、20 张政策卡；并对 EP04 当前候选和 v20 的已审事件做了 3 条语义边界复核、2 条执行问题复核、7 条新事件的路由。代码已经接通未来新包的 `start --event-history-run → review_bundle/event_routes.json`，但当前 label-loop 有保护中的空白草稿，因此不回填侧车或更新页面。该结果仍不构成训练 gold 或自动语义删剪政策；下一步是在独立新审核包上验证路由是否真的减少重复审核而不漏检。

2026-08-17 的有效闭环是 `main/orchestrator/label_learning_driver.py` + 项目内 `$label-learning-driver`：普通 `delivery_orchestrator start` 默认加载冻结 v3 快照，在候选冻结前后自动生成带目标 `run_identity`/`input_manifest` 的 pre/post 侧车；独立 `evidence` 入口生成按节目留出、排除同节目/同 source bundle 的防泄漏回测和只读 shadow，并保存目标审核包/草稿 before/after 哈希。它不训练黑盒模型，不接触音频，也不修改当前审核包。机器建议只能用于排序、提示和后续 `machine_assisted_draft` Challenger；`human_approved`、EDL 与 `autocut_policy` 仍完全由其他人工闸门控制。2026-08-17 起，"≥3 期节目 / ≥2 位独立审核人"两条数据规模 blocker 已按项目负责人明确指令从 driver 与 policy_promotion 中移除；`INSUFFICIENT_DATA_FOR_CROSS_EPISODE_GENERALIZATION` 现在只在 `source_audio_sha256` / `source_bundle_sha256` 身份覆盖不完整（防泄漏门）时出现。

同日新增的 `main/orchestrator/case_memory.py` 把“相似案例检索”从只读实验变为未来**普通新 run**的审核辅助：它从 run-local 冻结快照检索同家族且有精确文本、文本+上下文或多项结构证据的历史真人案例；输出历史决定、备注、匹配理由、相似度与身份状态。`case_memory.pre_review.json` 覆盖全部候选并影响低风险代表样本的优先级，`review_bundle/case_memory.json` 仅绑定该审核包的 `review_manifest_sha256` 并供页面/离线审核包展示。高风险全审、真人决定、EDL 和 autocut 政策都不受它改变。

检索必须排除目标 run、同一节目、同 source bundle 与同源音频；旧案例身份不完整时只能作为标明限制的历史参考。`resume` 复核两份侧车的 SHA、候选源/覆盖、冻结快照、run/input 身份和审核包绑定；活动草稿会阻止向审核包补写侧车。当前有单元、集成和 orchestrator 行为回归证据，但还没有一份新真实音频审核包的运行证据，因此它不是已证明能减少审核时间的学习成果。

### 自动剪辑政策的独立晋升门（2026-08-16）

为避免 Agent 把“用户叫我去生产”误解成“可以跳过证据”，项目新增 `main/orchestrator/policy_promotion.py`。它把 policy-card 快照、规则建议、readiness、独立 benchmark/复核/回滚证据和负责人签署范围一起评估，生成可追溯的 `PROMOTION_REPORT.md/json`。该工具是证据门，不是训练器或删剪器：报告不通过时，`autocut_policy` 必须保持 `NOT_APPROVED`。

当前报告已实际运行，结果为 `NOT_APPROVED`。独立封存 run 是 `main/runs/POLICY-PROMOTION-v1-20260816/`；原因是只有 2 期、1 位审核人、无独立 benchmark/复核/回滚演练，且没有具体的低风险删除白名单签署。该报告还区分了“保护性规则”和“自动删剪规则”：`editing-policy-guards-v1` 已在未来新 run 的入口启用，能够 preserve/block 已知 ASR 词边界误报或升级人审；它不会减少任何语音内容，更不能被包装成自动剪辑权限。

## P0、P1与未来学习

- P0 让输入特征可信：字、时间戳、VAD、说话人、重叠。
- P1 让人工标签可信且高效：高风险全审、低风险代表性抽样、删、留、未来的改边界以及理由和时间。
- 内部经验循环以后才用多期标签训练或调优 Challenger。

## 未来监督学习样本

输入 X 可包括候选文字和上下文、停顿/重复特征、说话活动、重叠、音频特征、风险词、候选理由和相似历史案例。

标签 y：

```text
accept / reject
若未来恢复 adjust：new_start_sample + new_end_sample
附 reviewer、理由、版本和时间；`review_mode` 仅作可选兼容元数据
```

只保存原音频和最终 MP3 属于弱监督，不能可靠推断剪辑意图。

## benchmark 与晋升

编辑 benchmark 必须独立于训练集，并覆盖：

- 候选接受率/precision；
- 人工真正想剪的内容被找到多少/recall；
- reject/adjust 比例和边界误差；
- 高风险语义误删；
- 无候选区域抽查；
- 跨节目、说话人和录音条件表现。

不能只看 accuracy，因为全部“不删”也可能得到虚高准确率。

## 启动真正参数化学习的经验门槛

当前二元候选排序研究的初始门槛是：至少约 10 期真实逐项审核、500 条有效 `accept/reject` 决定、`reject` 占比避免极端失衡、冻结独立 benchmark、独立复核和回滚至少演练一次。`adjust` 未来用于边界学习增强，但不是当前二元排序的前置条件；`review_mode` 不再作为案例入库或规则分析门禁。

这些是经验性安全门，不是科学定律。数据多样性和错误成本比单纯数量更重要。

## 演进顺序

```text
真实审核记录
→ 高风险全审 + 低风险校准样本
→ 机器预测与人审标签分离留痕
→ 规则/阈值改进
→ 相似案例检索
→ 候选风险与排序
→ 小型 GBDT 等排序器
→ 数据足够后才考虑序列模型或微调
```

不建议短期从整段波形端到端训练，标签规模和解释性都不支持。

## 安全边界

- 生产中禁止在线学习和静默改规则。
- bulk accept、伪 reviewer 与 machine_proposed_* 不进入真人训练标签；review_mode 仅保留为兼容元数据。
- 机器预测只能作为机器辅助试听草稿、离线评测或未来有标签对照的校准资料；不能因为机器自己写了 accept 就回流为训练真值。
- Challenger 必须离线挑战冻结 benchmark，由独立人员复核并人工晋升。
- 新版必须可复现、可回滚。

## 2026-08-17 自动刷新与可信来源边界

每次有效人审标签由 `/api/save` 保存后，系统现在自动生成新的不可变经验快照 run，并把活动指针切换到该快照：具名真人 + 至少一条 `accept/reject` 才有资格；pending 行不会进入学习。服务端把有效子集写为 `human_decisions_and_feedback.live.json`，再生成一个 `LABEL-LEARNING-AUTO-*` 运行目录。系统使用稳定的“标签内容 SHA”去重，所以纯 session/试听时间变化不会重复建立快照，accept/reject、候选语义 SHA、审核人或备注变化才会建立新快照。每个自动 run 还冻结触发它的 live 标签源文件，避免以后继续审核时丢失历史证据。若同一具名审核人将所有有效标签撤回为 `pending`，系统冻结撤回草稿和旧 live 标签、用排除旧标签的输入重建快照；只有成功后才移除 live 标签并切换指针，失败则恢复原文件与旧指针。这里的“写回生产”只表示未来 `start` 读取新的经验证据、更新审核排序和保护性规则；不表示在线训练、Champion 晋升、EDL 生成或无人审核删剪。快照构建失败必须 fail closed，活动指针保持旧值，并允许下次相同保存重试。

负责人确认历史逐项标签均为本人审核，因此标签来源可标为 `USER_CONFIRMED_HUMAN_LABELS`。这不会替缺失的 `source_bundle_sha256` 造身份：防泄漏回测仍按可证明的音频/节目/审核人独立性计算，证据不足就显示 `INSUFFICIENT_DATA_FOR_CROSS_EPISODE_GENERALIZATION`。

**真实回填状态（2026-08-17）**：负责人已授权使用既有标签，`EP04-review-product-v2` 的 13 条具名真人决定已生成新的不可变 `LABEL-LEARNING-AUTO-HUMAN-BACKFILL-20260817-001` 快照并成为活动指针。该快照仍为 65 条独立逻辑事件、20 张政策卡；对当前 12 条候选的只读 shadow 保持目标审核包完整性 `PASS`，并保守输出 12 条 `HUMAN_REVIEW_REQUIRED`。因此它证明“人审数据已被实际接入和消费”，不证明“系统已经可以少审或自动删剪”。

英文术语是独立的 ASR 质量门：固定模型、音频和解码参数，仅比较 `zh` 与 `auto` 两臂；以真人确认的术语 gold 计算 exact term match、omission、split/merge error 和中文回归。未完成该门之前，任何 A/B 结果都只能是 Challenger。
