# F01 输入检查与同步

## 功能目的

确认同一期任意 N 条 WAV 的格式、授权和时间线是否可靠，决定能否直接同步处理、需要校正，还是必须停下来人工判断。

流程位置：`N 轨 WAV → 输入检查与同步 → 降噪`。

## 输入与输出

输入：一条或更多原始 mono WAV、轨道标识/角色、节目编号和授权信息。

输出：

- 输入格式、时长、采样率、位深、峰值和 SHA-256；
- BWF/time reference 等元数据；
- 起始偏移与时钟漂移估计；
- `accept_zero / correct / manual_review` 一类同步决定；
- 校正参数和证据。

## 当前状态

### 已验证事实

- EP03 两轨来自同一 Zoom H6 会话，采样率、样本数、创建时间和 BWF `time_reference` 一致，本期冻结为零偏移、零漂移。
- 已用已知 75 ms 起始偏移 + 100 ppm 漂移的合成 fixture 验证多窗口估计和校正；校正后残余约 1 ms。
- 真实 EP03 声学相关只有部分窗口达标时，自动校正会被拒绝，而不是强行套参数。
- 当日三轨兼容夹具的 3 条音轨均为 48 kHz、960,000 samples，N 轨共同时间线检查实际通过。

### 待验证假设

- 两台真实独立设备上的 drift 检测与校正是否足够可靠。
- 不同噪声、说话交替和长静音条件下的置信度门是否合理。

## 安全边界

- 原始 WAV 只读。
- 低置信度不得自动校正。
- 所有校正必须保持可回到原始 sample 的映射。
- 同机元数据证据与声学相关证据必须分别记录，不能互相伪装。

## 验收标准

- 格式异常、长度不一致和缺失元数据能被明确报告；
- 已知 offset/drift fixture 的估计误差在预设门限内；
- 低置信度样本 fail closed；
- 至少一组两台真实设备素材通过完整验证；
- 下游使用的每条音轨有明确时间线版本与 SHA。
