# F05 人工审核、校准标签与机器辅助判断

> 当前状态指针：当前 run 和审核数量以 CURRENT_DELIVERY_FACTS/《当前状态摘要》为准；本文件只定义审核、备注、标签和机器预测的契约，不复制某一版 run ID。

## 功能目的

让真人只把时间花在机器无法安全决定的内容上，同时把真人的决定保存成可追溯的校准证据。流程不是“机器打 accept，再当成人审”，而是：

~~~text
全量候选冻结
→ 高风险全审 + 低风险分层代表样本
→ 真人 accept / reject
→ Agent 仅据冻结规则、经验快照和本轮标签做全量预测
→ 人审版 + 机器辅助试听版
→ 整片人工听审
~~~

完整交付规则见《Agent交付流程-从音频到成片》。本文件定义审核与标签的边界。

## 2026-08-14 当前实现事实

历史 v20 已完成逐项决定与渲染；当前可继续审核的 run 只以《当前项目进度》的 `CURRENT_DELIVERY_FACTS` 为准。截至 2026-08-16 是 `EP04-label-loop-v1-20260815-1805`，它复用了已经验证的外部
`faster-whisper small` 词级中英转写和 `semantic-transcript-v1`，没有重新换 ASR。审核页必须同时提供：

- 带明确提示的句子/分句辅助上下文；原始词级 ASR 仍是时间边界证据；
- 每候选可选 `feedback` / 备注；
- localStorage 与 `review_draft.json` 草稿保存；
- 每次 `/api/save` 有效保存后，`review_draft.json` 保留可恢复草稿；若已有真实具名审核人的 `accept/reject`，服务端同时更新只含有效标签的 `human_decisions_and_feedback.live.json`，立即刷新未来新 run 的经验快照。最终 `/api/submit` 再写完整的 `human_decisions.json`、`calibration_report.json`、`feedback_bundle.json` 和正式 EDL 草案；所有链路都保留备注。

`feedback` 是正式审核契约的一部分，不是可随前端精简而删除的装饰字段。若页面没有备注框、草稿保存或后续透传，当前审核包必须标记为不可用并先走 `refresh-review`；不得让审核人先打标签、事后再猜反馈。

审核页或字段发生变化时，不得直接改写带 `ui_sha256` 的 `review_bundle/index.html`。没有草稿和正式决定时，才可按《版本同步与交付事实门》使用 `refresh-review` 归档旧包、从同一候选源重建，并检查候选边界没有变化。只要已有 `review_draft.json` 或 `human_decisions.json`，该审核包即冻结：不得 refresh、替换页面、加路由侧车或扩大候选；未来 canonical 前端只能用于下一次新审核包。同步检查必须同时验证冻结页面 SHA、冻结页面的备注/草稿/上下文能力，以及草稿对 package/manifest/候选语义 SHA 的绑定。

审核页面还必须把四种不同信息分开：本次 `run_id`、候选规则/偏好版本、风险路由、规则命中置信度。`review_package.json` 的 package-level `review_scope` 必须从本轮冻结的校准选择报告复制高/低风险 ID 与数量，前端只能显示这一证据，不能自行猜风险。候选“置信度高”只表示规则命中把握，既不等于高风险，也不等于 Agent 可以自动剪；页面不得把候选规则的版本号写成当前交付 run 的版本。

## 四种结论，不得混用

| 结论 | 谁产生 | 含义 |
| --- | --- | --- |
| human_accept / human_reject | 真人 | 对当前候选、当前边界的明确决定 |
| machine_proposed_accept / machine_proposed_reject | Agent | 基于规则、模型或校准的预测，绝非真人标签 |
| auto_cut_eligible | Agent + 有效政策 | 满足明确、已启用 autocut_policy 的机器预测；仍保留机器 provenance，只在最终人工 QC 后允许走政策授权交付路径 |
| human_review_required | Agent | 高风险、边界样本、政策外或校准不足，必须回到真人 |

human_decisions.json 只能包含真人决定。机器预测必须在单独的 prediction_manifest.json；每一条都写明 policy、阈值、规则/模型版本、校准报告 SHA 和 decision_provenance。

## 反馈归类与标签学习闭环（2026-08-16）

`feedback` 不是自由文本终点，而是后续归类的输入。归类必须保留原备注，并输出一个可审计的 `feedback_classification`：

| 类别 | 解释 | 对后续候选的允许影响 |
| --- | --- | --- |
| `asr_error` | 字、英文专名、词边界或时间戳识别错 | 修正匹配/展示或阻断候选，不改变原始 ASR |
| `semantic_keep` | 语义完整句中的口语词、认可、连接词等应保留 | 生成保留政策候选，不能自动删 |
| `semantic_cut` | 在当前上下文中确实可剪 | 形成 Challenger 候选/排序证据，仍不等于授权 |
| `execution_issue` | 剪辑痕迹、音量变小、回声、crossfade 或边界不自然 | 进入边界/渲染修复，不反转语义决定 |
| `false_positive` | 候选本身不应出现 | 抑制同类提名并记录反例 |
| `unknown` | 备注不足或无法稳定归类 | 保持人工审核，不生成政策 |

归类结果必须带 `case_id`、原备注 SHA、证据候选、适用条件、反例、归类器版本和 reviewer；它不能覆盖真人 `accept/reject`。相同 `event_key` 的新候选先查事件账本：精确重复也只提供历史决定/备注参考，不能自动变成本轮决定或 EDL；边界变化更只能复用语义线索并要求执行复核。只有未来经人工晋升的去重政策才能改变新审核包的默认排序/抑制行为。

归类案例进一步生成版本化政策卡，初始状态为 `challenger`。政策卡只有在历史回归、独立样本和人工复核通过后，才能影响 `machine_assisted_draft`；任何状态都不能自动生成 `human_approved` 或修改 `autocut_policy`。

### 已验证 Challenger 产物

`LABEL-LEARNING-v2-20260816` 因重复计数和 manifest 失效只保留为历史诊断。当前有效的 `LABEL-LEARNING-v3-20260816/preference_snapshot/` 已实际输出 65 条独立逻辑事件（24 accept / 41 reject）、`feedback_classifications.jsonl`、20 张 `policy_cards.json` / `policies.md`。一条备注可同时保留“语义保留/可剪”和“执行问题”两层信息；未知或无备注只留在案例库，不伪装成政策。该分层避免把一次听感反馈扩大成全局自动规则。

### 可执行标签学习驱动器（2026-08-16）

`main/orchestrator/label_learning_driver.py` 是把有效快照真正作用于**新候选**的唯一入口。它对每条完整候选输出 `MACHINE_CUT_SUGGESTED`、`MACHINE_PRESERVE_SUGGESTED` 或 `HUMAN_REVIEW_REQUIRED`，同时保留匹配 case_id、反例、语义票数、执行风险与缺失特征。它把三件事分开：ASR/误报、语义剪留、当前剪口自然度；执行问题绝不能被学成“内容不该删”。

驱动器有两种运行方式：普通新 run 的 `delivery_orchestrator.py start` 默认冻结 `LABEL-LEARNING-v3-20260816`，在候选冻结前后自动写 `label_learning_application.pre_review.json` 和 `review_bundle/label_learning_application.post_boundary.json`，并绑定当前 `run_identity.json` / `input_manifest.json`；它只影响审核优先级与证据展示。已有草稿的冻结审核包只能在独立学习 run 生成 shadow。它不写 `human_decisions.json`、EDL、音频或 `auto_cut_eligible`。

每次独立回测和 shadow 应优先使用 `label_learning_driver.py evidence`。该入口在目标 run 外生成证据目录，记录驱动器源码 SHA、快照/候选输入 SHA，并对目标 run 的身份、候选、审核包、UI 和草稿做 before/after 哈希比较；任一变化即 fail closed。2026-08-17 的有效证据是 `main/runs/LABEL-LEARNING-DRIVER-v5-20260817/`，shadow 结果为 0 剪 / 0 保留 / 12 人审，目标完整性比较 `PASS`。旧 v4 的 1/3/8 结果因没有当前代码和目标完整性绑定，只保留为历史证据。

回测必须按节目留出，并排除同一原始音频身份。若 `data_quality.status=INSUFFICIENT_DATA_FOR_CROSS_EPISODE_GENERALIZATION`，原始命中率只能作诊断，不得称为模型准确率、不得成为"人只审五条"的依据。2026-08-17 起，"≥3 期节目 / ≥2 位独立审核人"两条 blocker 已按项目负责人明确指令从 driver 与 policy_promotion 中移除；`INSUFFICIENT_DATA_FOR_CROSS_EPISODE_GENERALIZATION` 现在只在 `source_audio_sha256` / `source_bundle_sha256` 身份覆盖不完整（防泄漏门）时出现。

### 相似案例记忆进入普通新审核包（2026-08-17）

`main/orchestrator/case_memory.py` 与标签学习驱动器并列：它不做预测，而是从本次 run 冻结的经验快照中为每一条候选检索可解释的相似真人案例。检索结果包含历史 `case_id`、节目/run、当时的 accept/reject、备注、相似度、匹配理由和身份状态。最低相似门要求同一候选家族外加精确文本、文本+上下文或至少两项结构证据，不能只因“同一类候选”就当作相似。

`delivery_orchestrator.py start` 先为所有候选生成 `case_memory.pre_review.json`，再在审核包建立后写 `review_bundle/case_memory.json`。低风险分层审核继续保留时长边界样本，剩余代表性槽位才由案例记忆的历史冲突/保留优先级占用；高风险仍全审。网页、离线 `review_packet.md` 都只显示历史参考；页面发现 `review_manifest_sha256` 不匹配会拒绝侧车。`resume` 会复核两份侧车 SHA、候选覆盖和源 SHA、冻结快照 SHA、run/input 身份及审核包绑定，任何漂移均 fail closed。

同 run、同节目、可证明同源 bundle 或同一源音频的案例不会进入通用案例记忆；来源身份不完整的旧案例可见但明确标为非独立证据。案例记忆不写 `human_decisions.json`、EDL、音频或 `autocut_policy`。当前实现已有 3/3 单元测试、3/3 接入契约和 12/12 orchestrator 回归（含优先级行为与篡改侧车拒绝），但尚未用新的真实音频审核包运行；当前 `EP04-label-loop-v1-20260815-1805` 已有草稿，保持冻结，不补写该侧车。

### 生产自动剪辑政策晋升门（2026-08-16）

`main/orchestrator/policy_promotion.py` 是政策卡进入**自动语义删剪** `autocut_policy` 前的唯一检查入口。它只读政策卡、规则建议、训练/晋升 readiness 和可选的负责人签署范围，输出 JSON/Markdown 报告；不会修改 Champion、当前审核包、决定、EDL 或音频。

自动删剪的最低门包括：足够的逐项案例、冻结独立 benchmark、独立复核、回滚演练，以及明确的 `signed_by + signed_at + policy_ids` 低风险范围。**2026-08-17 起，"多期节目 / 多位独立审核人"两条数据规模门已按项目负责人明确指令从 policy_promotion 中移除**；独立 benchmark / 复核 / 回滚三项过程质量门仍保留。高风险家族（长停顿、说错重来、语义重复、离题、串音/瞬态等）无论数据量多大都不能进入无人值守自动删剪。当前真实报告为 `main/runs/POLICY-PROMOTION-v1-20260816/PROMOTION_REPORT.md`，状态 `NOT_APPROVED`；仅识别到 preserve/block 型保护规则候选，不产生 `auto_cut_eligible`。

`editing-policy-guards-v1` 是与晋升门并列、但更窄的活动生产层：`delivery_orchestrator.py start` 会冻结其 SHA，并把每条结果写入 `policy_application.json`。它只能自动保留已知 ASR/词边界误报、或要求更高等级的人审；它不能把候选标成可剪、不能代填审核人、不能写 EDL。这样可以立即减少“完整词被误剪”的风险，同时不把少量标签误当成无人删剪授权。

未来新 run 已接通 `start --event-history-run <历史逐项人审 run>`：它冻结历史来源 SHA，并在审核包生成后写入只读 `review_bundle/event_routes.json`。前端只显示路由、`matched_case_id`、历史决定参考和是否需要复听边界；不会写入 `state.decisions`。当前 label-loop 因已有草稿而明确不补写这个侧车。

## 审核策略

### 必须全量人审

以下类别无论预测分数如何，都不能只靠机器进入人审批准版：

- 数字、专名、否定、结论、承诺、敏感表达、话题转折和明显离题；
- 说话人切换、重叠、串音归属不清、其他轨有不同文字；
- 长停顿压缩、咳嗽/碰麦、爆音、音乐干扰等听感事件；
- 说错重来、远距离语义重复、整句语义重复；
- 边界不清楚、删得过长，或跨轨守卫为 BLOCKED / ambiguous。

长停顿必须听原版与压缩版 A/B；现行 filler-global-pause-v1 已在后端约束这个规则。

### 低风险代表性审核

连续、规则清楚的口癖或紧邻重复可不先让人逐条看完。Agent 必须：

1. 按 reason_family、reason_key、置信度档、时长档和轨道活动分层；
2. 每层抽至少 3 个；样本很多时抽 10%，上限 10 个；
3. 额外纳入最靠近阈值的边界样本；
4. 固定随机种子并记录抽样过程；
5. 样本不足、类别混杂或人工意见不稳定时输出 INSUFFICIENT_DATA，全部升级人审。

这意味着“真人只看高风险和最有代表性的候选”，但不意味着系统可以跳过真人的审计痕迹。

## 人工决定记录

当前界面只开放 accept / reject；adjust 暂时禁用，边界不合适时应 reject 并备注。每个真人决定必须保存：

- 当前 `episode_id`、`run_id`、`run_identity.json` SHA，以及候选是否来自本次 run；
- reviewer、reviewed_at、候选与审核包 SHA、原始边界；
- decision、可选理由、`feedback`（最多 500 字）和 review_basis；
- 试听过时的 preview SHA 和时间；
- 对必须听的候选，原版与拟删版试听证据。

审核不以“必须打开前端”为前提。普通新 run 同时生成：

- `review_packet.md`：按候选列出时间、文本上下文、原版/拟处理版的本地试听路径和应答方式；
- `review_decisions.template.json`：仅是给 Agent 整理真人回复的空模板，包含占位符，**不是**已审核文件；
- `review_bundle/`：保留完整哈希绑定审核包，供需要时用本地网页复核。

审核人可以只回复例如 `C001 accept（已听 A/B）`；Agent 再根据真人的明确回复、真实姓名和实际试听时间写入 `human_decisions.json`。不得把模板、Agent 自己的判断或“已生成审核包”写成真人决定。审核包会保留 `candidate_kind`、候选说明和 `review_requirements`；长停顿等标为高风险的候选在前端保存和 `resume` 两处都会强制记录原版与拟处理版 A/B，缺一项即拒绝继续。

机器不得代填 reviewer、代点确认、把历史平均接受率复制成真人 accept，也不能用 LEARNED_FROM_HUMAN 之类字符串冒充审核人。

`human_decisions.json`、`calibration_report.json` 与 `prediction_manifest.json` 必须引用相同
的 `episode_id/run_id` 和 `run_identity.json` SHA。审核包、候选、EDL 或预测若来自另一个
run，即使文字看起来相同，也必须重新校验或重新审核；不能把旧绝对路径、旧 package_id
或旧 episode 名复制进新 run。

候选可能引用 `editing-preference-profile-v12-draft` 之类的偏好快照，但该字段只说明候选
为何被提名或如何排序。它不能替代 reviewer、校准报告、风险分层或 `autocut_policy`，更不能
让高风险候选变成机器可预测的低风险项。

## 两份 EDL 与交付含义

~~~text
human_approved.edl.json
  = 仅 human_accept

machine_assisted_draft.edl.json
  = human_accept + 通过安全门、且本轮校准后为 machine_proposed_accept 的低风险机器剪口
~~~

无论 autocut_policy 是否签署，机器都应把通过安全门、校准充分的低风险 machine_proposed_accept 剪入 machine_assisted_draft，供人整片试听；但不得把机器剪口混进 human_approved EDL。autocut_policy 只决定机器剪口能否在最终整片人听审、QC 与负责人确认后走政策授权交付路径，绝不改变其机器 provenance。

### 单次负责人授权的机器试听例外（2026-08-17）

当负责人明确指定某一集可暂时忽略**历史标签来源身份不完整**的问题时，系统可以新建独立 run，生成一份仅含 `machine_assisted_draft` 的试听 EDL。例外必须写入该 run 的授权 JSON、plan/checkpoint、机器预测和每一个 EDL action；每个动作仍标为 `machine_prediction` 或 `user_authorized_same_episode_machine_draft`，并列出历史 case、当前边界与当前剪口质量。

此例外绝不允许伪造 reviewer、写 `human_decisions.json`、生成 `human_approved.edl.json`、改 `autocut_policy` 或改变 Champion；不得反过来修改 label-learning 的跨节目防泄漏规则。它只解决本次负责人已授权的本地试听需求，最终仍必须由负责人整片听审决定继续迭代、REWORK 或另走人审版。

#### 已执行的低前置审核口径

负责人可以为**一个明确 episode、一个明确本地 run**授权“先出机器试听稿”。这时前置审核标准改为：

1. 已有同一期逐项标签被负责人确认可信，即使旧记录的来源身份字段不完整，也可作为机器证据；
2. 不要求审核人再次逐条点击后才第一次渲染；机器剪口仍必须是低风险，且当前边界或复用边界 `artifact_risk=OK`；
3. `semantic_keep`、已知 ASR/完整词误报和明确保留反馈优先机器保留；`BLOCK`、跨轨冲突、高风险、语义未知及未修复执行问题保持不剪；
4. 历史 `reject` 只说“剪辑痕迹/声音异常”时，不能被当作语义保留。只有当前重选边界已通过执行检查时，才能作为“修复后重试”的机器试听剪口；
5. 输出只可以是 `machine_assisted_draft`。第一次试听后的负责人整片听审才决定继续、返工或另走 `human_approved`，但不把本次机器动作改写为新的人审逐项标签。

EP04 的 `EP04-machine-assisted-draft-20260817-002` 是该规则的真实运行：3 剪、3 保留、6 条留待迭代。它证明“降低前置审核门后能出本地试听成品”，不证明跨节目自动剪辑或发布资格。

### 冻结整片试听批准的窄例外

若负责人已实际听完一个**具 SHA、不可变且范围明确**的试听成片，并明确批准该整套动作，
Agent 可为该特定 run 写 `human_whole_episode_audition` 批准范围，并将该冻结动作集合封装为
本期 `human_approved` 交付。这不是逐项审核的替代品，必须同时满足：

- 记录原始试听 WAV/MP3、EDL、音乐和动作集合的 SHA；
- `human_approval_scope.json` 明确说明批准的是整片范围，不能伪造 reviewer 或逐项 `human_accept`；
- 原机器/Challenger provenance 保留在每个动作上；
- 不导出训练标签、不修改 Champion/规则/偏好快照、不授权下一期自动剪辑。

EP04 v12 的新封装 run 使用的正是此例外：用户明确听完并批准冻结的 v12 成片，而不是声称
588 个历史动作都做过逐项点击审核。

## 2026-08-17 每次有效标签保存后自动刷新经验快照

负责人确认已有逐项记录均由本人审核，故其 `human_accept / human_reject + feedback` 可进入可信人审来源集合。系统仍不得从文件名推测缺失的音频身份；这只影响防泄漏泛化资格，不否定真人标签本身。

服务端 `/api/save` 在每次草稿自动保存时，先严格校验候选与语义 SHA。若审核人是具名真人且其中已有一条或多条 `accept/reject`，它会：写草稿 → 抽取 `human_decisions_and_feedback.live.json`（pending 不进入）→ 冻结该 live 源文件到新的不可变 `LABEL-LEARNING-AUTO-*` run → 重建快照与回测 → 校验来源 SHA → 原子更新活动快照指针。只改 session 结束时间、试听时间或 metrics 不会重复刷新；改 accept/reject、候选语义 SHA、审核人或备注才刷新。若刷新失败，草稿与 live 标签侧车保留、指针不动，下次相同有效保存会重试。

若审核人撤回最后一条有效标签：同一具名审核人把该包全部决定改回 `pending` 后，服务端会冻结草稿和旧 live 标签，重建一份**排除旧 live 标签**的快照；新快照和回测成功后才删除旧 live 标签并原子切换指针。若切换失败，旧 live 标签自动恢复且指针保持不变。最终 `/api/submit` 仍验证“每条候选都有明确 accept/reject”，写 `human_decisions.json` 和 EDL 草案，并再做一次完整决定的严格刷新。活动指针只改变未来新 run 的审核优先级、历史提示和 preserve/review guards；它不得创建本轮决定、EDL、音频或自动语义删剪政策。

快照重建不是在线训练：它是版本化、可回滚的经验材料更新。每个新 run 冻结自己使用的快照 SHA，因此同一审核包不会因提交后指针变化而漂移。

**实际启用证据（2026-08-17）**：负责人已授权把既有真人审核正式交给学习层。`EP04-review-product-v2` 的熊镇正 13 条逐项 accept/reject 已触发 `LABEL-LEARNING-AUTO-HUMAN-BACKFILL-20260817-001`，活动指针已更新。对当前冻结的 label-loop 包进行独立 shadow 后，before/after 完整性为 `PASS`，结果为 0 条机器剪、0 条机器保留、12 条仍须人审；这不是失败，而是当前证据不足时的保守行为。
