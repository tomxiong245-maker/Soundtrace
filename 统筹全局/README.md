# 统筹全局：文档入口

这里不再堆叠每次对话的长摘要。文档分为四类：

| 你要解决的问题 | 阅读 |
| --- | --- |
| 产品是什么、总体架构怎么安排 | [`全局统筹记忆.md`](全局统筹记忆.md) |
| 现在完成了什么、卡在哪里、下一步是什么 | [`当前项目进度.md`](当前项目进度.md) |
| 当前最好成片、最新审核包和剩余门分别是什么 | [`最终版本审计-20260814.md`](最终版本审计-20260814.md) |
| 新 Agent 拿到音频后到底怎么交付 | [`Agent交付流程-从音频到成片.md`](Agent交付流程-从音频到成片.md) |
| 什么才算 MVP 真的完成 | [`产品要求与验收标准.md`](产品要求与验收标准.md) |
| 某个小功能具体在做什么 | [`功能说明/README.md`](功能说明/README.md) |
| 现有 Skill、脚本、Tool、库在哪里，能不能调用 | [`能力目录.md`](能力目录.md) |
| benchmark、Skill-first 与未来监督学习怎么安排 | [`功能说明/F10-基准、能力目录与Skill路线.md`](功能说明/F10-基准、能力目录与Skill路线.md) |
| 想在工作中系统学习监督学习与 Skill | [`学习路线-监督学习与Skill.md`](学习路线-监督学习与Skill.md) |
| 开发与文档怎样保持不乱 | [`开发与文档规则.md`](开发与文档规则.md) |
| 防止 run、前端和 Markdown 说法漂移 | [`版本同步与交付事实门.md`](版本同步与交付事实门.md) |
| 后续可以优化但不阻塞 MVP 的事情 | [`待优化清单.md`](待优化清单.md) |

| 旧设计、旧进度和重构前文件 | `归档/`，默认不读 |

## 更新原则

- 总体方向只写《全局统筹记忆》；
- 当前状态只写《当前项目进度》；
- “只输入音频”的操作顺序、人工闸门和双交付物只写《Agent交付流程-从音频到成片》；
- 要求只写《产品要求与验收标准》；
- 功能现状只写相应 Fxx；
- 命令、日志、SHA 和单次实验报告不写在这里，留在对应 run 或 Challenger；
- 旧文件归档后不再作为事实来源。
