# 产品要求与验收标准

> 作用：回答“我们到底要做什么、什么才算完成”。实现细节和单次实验数字写在对应 run，不在这里冒充长期规范。

## 1. 产品目标

为中文多人对谈播客提供一个本地、可追溯的多轨后期助手：机器完成检查、转写、候选准备、校准预测、同步剪切、固定音乐和技术 QC；真人只在语义、听感和发布决定真正需要判断的位置介入。

目标不是“机器删得越多越好”，而是：

~~~text
净节省时间 = 原人工剪辑时间 - 审核时间 - 返工时间 - 系统维护时间
~~~

## 2. 用户输入与默认交付

当节目配置已经冻结，用户只需提供：

- 同一期的一条或多条对齐 mono WAV；
- 节目编号；
- 若已知则提供 speaker-map.json；未知时显示物理轨 ID，不阻塞；
- 授权状态由配置或负责人确认。

Agent 自动读取固定规则、经验快照、音乐素材和模板，创建新 run；用户不需要手工找脚本、拼命令、挑音乐或整理产物。

默认交付至少包括：

- 人工采用的 human_approved 试听/渲染版；
- 机器辅助 machine_assisted_draft 试听/渲染版；
- 全量候选、校准审核包、真人决定、机器预测、双 EDL、音乐 manifest、QC 和 DELIVERY_REPORT。

若没有真人闸门、有效政策、整片听审或发布规格，输出必须明确叫草稿/技术样片/HOLD，不得叫发布候选。

## 3. 功能要求

### FR-01 输入安全

- 原始文件只读，记录 SHA-256、格式、采样率、位深、声道、样本数和时长；
- 不是同一期、不是独立 mono、未授权、无法建立共同时间线或固定音乐校验失败时停止；
- 不自动猜测缺失文件、轨道身份或节目类型。

### FR-02 同步与时间线

- 检查 offset、clock drift 和共同整数 sample 时间线；
- 证据不足时拒绝自动校正；
- 所有全局剪口同步作用于全部语音轨。

### FR-03 音频分析

- 保留原始与处理轨；
- 输出词级 ASR、VAD、轨道活动、重叠/串音提示和声学事件证据；
- 未知人物、主讲和重叠必须保留 unknown/ambiguous，不用男女猜测替代。

### FR-04 候选与安全

- 全量候选先冻结，再按风险分层；
- 高风险候选全量人审；低风险候选用固定种子做分层代表性审核；
- 长停顿、说错重来、离题、整句语义重复、串音归属不明、咳嗽/碰麦和所有边界不确定项默认必须人审；
- 候选不能直接修改成片。

### FR-05 人工校准与机器预测

- 真人决定使用 human_accept / human_reject，写入 human_decisions.json；
- Agent 的全量判断使用 machine_proposed_*、auto_cut_eligible 或 human_review_required，写入 prediction_manifest.json；
- 机器必须保留 policy、规则/模型版本、阈值、校准报告 SHA 和 provenance；
- 当前 autocut_policy = NOT_APPROVED，因此机器预测只可进入 machine_assisted_draft，不可伪装成人审或发布批准。

### FR-06 EDL 与渲染

- 同时生成 human_approved.edl.json 与 machine_assisted_draft.edl.json；
- 前者只含真人采用的全局剪口，后者加入通过安全门、经本轮校准的低风险机器预测剪口；
  有效政策只决定机器版能否在最终听审后走政策授权交付，不能改变机器来源；
- 两份 EDL、输入轨、审核/预测材料和 render manifest 必须哈希绑定；
- run 目录、`run_identity.json`、EDL、输出文件名和所有 manifest 的 `episode_id/run_id`
  必须一致；否则 fail closed；
- source_track_gate 与全局语义剪口分开记录。

### FR-07 固定片头片尾音乐

- 使用配置指定且已授权的固定音乐，不生成或临时替换音乐；
- 当前素材 SHA 与 reference-linear-v1 时序见 F06；
- 素材缺失、SHA 不符、解码失败或模板无法满足时 BLOCKED；
- 音乐增益、ducking、LUFS、true peak、MP3 规格在 Mentor 冻结前不能被实验值冒充。

### FR-08 QC 与交付

- 自动 QC 检查格式、哈希、时间线、剪口、音乐、响度、峰值和编码；
- 真人 QC 复听高风险剪口、整片、片头片尾和无候选区域；
- DELIVERY_REPORT 明确输入、候选、人审、机器预测、双版本、音乐、QC、风险和最终状态。

### FR-09 经验与晋升

- 逐项真人决定可进入案例库、Skill/规则分析；
- bulk accept、伪 reviewer 和机器预测不进入真人训练标签；
- 新规则/模型只能在 Challenger 离线评测，通过冻结 benchmark、独立复核、人工晋升和回滚后成为 Champion；
- 禁止在线静默学习和自动改生产规则。

## 4. 非功能要求

- 真实音频、转写和内部资料默认只在本机；
- 同样输入、版本和参数应可复现；
- 阶段失败可安全续跑，不覆盖正确历史产物；
- 证据必须区分静态代码、自动测试、真实运行、真人审核和发布验收；
- 适配 Apple M3 / 16 GB，不以破坏系统环境换取短期运行。

## 5. MVP 不包含

- 视频剪辑、TTS、AI 音乐、自动发布；
- 无人审核的高风险语义删除；
- 在线监督学习或自动晋升；
- 复杂专业 NLE 的完全替代。

机器辅助试听草稿属于本项目目标，但在有效政策和最终人工听审前不等于发布成片。

## 6. MVP 完成门

### A. 技术链路

- 一整期真实多轨从音频目录到审核包、双 EDL 和至少一份渲染版无需人工拼命令；
- manifest、哈希、时间线、编码、音乐和 QC 通过；
- 失败、过期材料和参数变化 fail closed。

### B. 人工校准

- 高风险全量审核；
- 每个低风险分层有固定抽样、边界样本和有效真人决定；
- 无 pending、默认接受或伪 reviewer；
- 机器预测与真人决定分离可追溯。

### C. 内容与听感

- 无误删结论、吞字、突兀剪口、明显串音误判或音乐盖人声；
- 高风险剪口和整片通过人工听审；
- 无候选区域完成抽查。

### D. 发布

- Mentor 冻结 LUFS、true peak、码率、音乐增益/ducking 和参考成片定位；
- WAV/MP3 符合规格；
- 负责人明确选择发布候选；否则保持草稿或 HOLD。

### E. 效率与数据

- 保留全量候选、真人标签、机器预测、EDL、理由、边界和 provenance；
- 2026-08-17 起，"记录手工基线/审核/返工/维护时间以证明净节省时间为正"这一 benchmark 条款已按项目负责人明确指令从 benchmark 判据中撤销。产品长期愿景公式（§1）保留作为方向叙述，但不再作为 benchmark 完成门或 Champion 晋升门。

## 7. 当前事实

- EP04 旧去重链路已完成 13 项真人双态审核，6 个同步剪口和技术试听版；
- EP04 口癖/长停顿 3 项已真人决定 2 删 1 留，但该轮独立 EDL/渲染和整片听审仍是门；
- EP04 v4（2026-08-13）有 122 条机器推断、86 个同步剪切、92 个源轨 gate、含音乐 WAV/MP3；不能称真人审核、发布候选或政策已启用；
- 固定音乐素材和目标时序形状已从 Mentor 成果学习并写入 F06，但音乐增益和发布规格未冻结；
- `delivery_orchestrator.py` 已实现最小可恢复入口和双 EDL 正式契约；EP04 v12 已以整片人听审批准 scope 形成正确身份的交付 run，并对冻结母带独立重测了响度。常规新节目仍只覆盖口癖/全轨长停顿，需要显式配置、受审计的本机 FFmpeg，且没有有效 autocut_policy、automix 或 Mentor 冻结的发布规格。

## 8. 外部工具接入

接入外部工具前必须记录来源、版本、许可证、权重 SHA、网络/遥测、数据流、资源占用、sample 数据契约、benchmark 和回滚方案。没有这些证据只能放 Challenger。
