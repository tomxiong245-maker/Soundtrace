# 2026-08-11 六点 MVP 交付说明

## 一句话结论

P0 和 P1 已从“只有骨架”缩成并跑通一个可演示的小产品：多轨本地转写 → 3 轨 A/B 审核 → 保存删除/保留 → 生成全轨同步 EDL → 导出 3 轨同步剪切后的 WAV/MP3。

这不是正式发布验收：今天新收到的三条真实 WAV 尚未出现在项目可见目录，真人 11 项审核尚未完成，ASR 也没有人工 CER。

## 负责人现在怎么用

### 1. 处理今天的三条真实 WAV

把三条 WAV 一起拖到：

`审核前端/P0-多轨转写/拖入音轨开始.command`

系统会按 `track_01 / track_02 / track_03` 编号，不猜男女。所有轨必须同采样率、同样本数、单声道；不满足就停止，避免错位。

### 2. 演示当前审核产品

双击：

`审核前端/challenger-review-product-v1/启动审核.command`

输入审核人姓名；默认先看“原转写”和红色标出的“拟删部分”，直接选择“采用剪切（删掉这段）”或“不剪（保留原音频）”。只有不确定时再展开“需要时试听（可选）”；不必听完才能选择。选中项会显示勾选和颜色，仍可改选；刷新后会恢复。这里不会删除原始 WAV。今天不开放改边界，边界不合适就选“不剪”。11 条完成后点击“完成并保存”。

轨 1/2 当前只代表物理麦 A/B；括号里的 `female/male` 是 EP03 旧文件标记，不是 AI 判断的性别。不同轨出现相似文字通常是串音。核心流程需要判断主讲/串音/重叠，不要求先区分男女。

### 3. 导出审核后语音

双击：

`审核前端/challenger-review-product-v1/导出审核后语音.command`

它会按照审核 EDL 同步剪全部轨道，输出每轨 stem、`speech_mix.wav` 和 `speech_mix.mp3`。自动测试 reviewer 默认不能当真人结果导出。

## 已实际验证的 benchmark

| 项目 | 结果 | 这说明什么 |
| --- | --- | --- |
| P0 三轨读取 | 3/3 成功；48 kHz；每轨 960,000 samples | 不是双轨写死，且时间线一致 |
| P0 时间戳 | 3 轨非法时间戳均为 0 | 可作为候选定位底稿 |
| P0 速度 | RTF 0.18–0.21 | 20 秒音频约 3.6–4.2 秒转写，快于实时 |
| P0 准确率 | 未测人工 CER；专名可见误识别 | 不能宣称“更准”或发布级字幕 |
| P1 审核包 | 3 轨、11 候选、22 A/B | 页面和材料契约支持 N 轨 |
| P1 浏览器 | 22/22 A/B 可解码 | 真实可听，不是只看静态 HTML |
| P1 后端 | 合法提交 200；`adjust` 400 | 保存链路和安全拒绝实际运行 |
| P1 EDL | 6 个自动测试删除均作用于 3 轨 | 同一剪口不会只删一轨 |
| 三轨渲染 | 3 stems + mix 均 909,600 samples；MP3 可解码 | N 轨同步剪切和最终出音频已跑 |
