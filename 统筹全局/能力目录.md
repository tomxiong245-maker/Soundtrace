# 音频剪辑项目：能力目录

> 目的：让项目负责人、Codex、Claude Code 不用翻完整仓库，也能找到“现在有什么、能不能用、入口在哪、不能做什么”。
>
> 标记：**已验证** = 有真实运行或浏览器证据；**Challenger** = 隔离实验，不能替换 Champion；**登记/骨架** = 有说明或代码，但未完成生产集成；**冻结** = 仅作资料或只读来源。

## 先看这张图

```text
顶层 Skill（判断与路由）
        ↓
Tool 注册表（能力名称、参数、脚本）
        ↓
执行脚本 / Challenger（真正处理音频）
        ↓
真人审核门
        ↓
EDL / 渲染 / QC
        ↓
案例库 → Skill/规则摘要 → 下一次 Challenger
```

`main/orchestrator/delivery_orchestrator.py` 已是最小稳定入口：它从同一期 WAV 建新 run，强制先做 DeepFilterNet、再接通 P0、口癖/全轨长停顿候选、校准审核、双 EDL/双渲染/QC 与交付报告；`orchestrator.py` 仍是旧状态机演示。其它候选家族、automix、发布规格和统一 Tool adapter 仍未接通，不能把这个入口说成全问题无人值守剪辑。

### Skill 的正确边界

```text
Skill = 工作方法 + 工具选择 + 安全边界 + 失败处理
Rule  = 当前可执行的阈值 / 字典 / 参数
Case  = 某一次真实审核的证据
Model = 未来可选的候选排序器，不是当前能力
```

不要把每个 `.py` 都叫成 Skill；也不要把每条案例直接写进 Skill。案例用于证明，Skill 用于归纳，Rule 用于执行。

## F. 最短调用原则

新需求不要先找脚本，先按这条路径走：

```text
1. 读顶层 SKILL：是否属于当前支持输入？
2. 查 Tool 注册表：已有能力叫什么、输入输出是什么？
3. 查本目录：它是已验证能力、Challenger，还是仅骨架？
4. 如果是 Challenger：新建隔离 run，不能覆盖 Champion。
5. 如果改变语义：停在人审，不得自动批准。
```

## 维护规则

- 新增一个可复用 Skill、Tool、外部库或独立 Challenger，必须更新本目录；
- 某项从 Challenger 晋升或被弃用，必须更新状态，不重写历史证据；
- 详细命令、哈希和某一期 run 留在原目录，不复制到此文件；
- 不把 Claude 当前施工的串音、咳嗽/碰麦、说错重来模块提前标成已完成；它们分别位于 `crosstalk-candidate-v1/`、`transient-events-v1/`、`self-correction-v1/`，施工期间不要写入或覆盖。
