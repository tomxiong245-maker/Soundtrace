# 音视频剪辑工作流：Codex 持久上下文

## 每次回答前的最小读取顺序

1. 读取 `统筹全局/当前状态摘要.md`；缺失或过期时运行
   `python3 main/orchestrator/context_checkpoint.py --write`。
2. 只读取本任务对应的一份 `功能说明/Fxx-*.md`。
3. 只有涉及当前版本、审核、ASR、音乐、渲染或哈希时，才读取
   `版本同步与交付事实门.md` 并运行同步检查。
4. 需要命令、哈希或旧证据时，按摘要中的 run ID 精确读取；归档默认不读。

完整 `全局统筹记忆.md`、完整 `当前项目进度.md`、全部 Fxx、旧会话和 run 日志不再是每轮必读。
它们仍保留为按需政策/证据，唯一当前事实是 `CURRENT_DELIVERY_FACTS`。

## 项目目标

为明略科技播客制作一个本地、可追溯、由真人掌握语义删剪决定的多轨后期助手，并安排后续可控持续改进架构。旧样例以双轨为主；2026-08-11 起按任意 N 条对齐 mono 轨设计，当前重点为三轨。

主流程：

```text
N 轨 WAV → 检查/同步 → 降噪 → ASR/VAD/说话活动
→ 候选与 A/B → 真人审核（当日 MVP 为 accept/reject，后续恢复 adjust）
→ approved EDL → 全轨同步剪切/crossfade → 混音/授权音乐/QC → WAV/MP3
```

当前 MVP 不包含视频剪辑、TTS、AI 音乐、自动发布、无人审核删除、监督学习训练或 Loop runtime 正式部署。

## 当前工作口径

- P0 是 ASR/VAD/轨道活动工具评测，不是训练剪辑模型；最小 faster-whisper baseline 已通过三轨工程门，人工 gold 和多引擎 verdict 仍未完成。
- P1 是审核产品与有效标签入口；离线学习闭环已从真实标签生成事件账本、备注多标签归类、政策卡和未来审核包的历史路由，但不是在线训练或自动审批。EP04 已完成 13 项真人双态审核、6 个三轨同步剪口和技术试听版渲染，仍缺 `adjust`、整片主观听审和发布收尾。
- 当日 N 轨小闭环只存在于 Challenger，已用一整期真实三轨跑到技术试听版，但未覆盖 Champion；正式集成、晋升和发布验收仍需单独完成。
- `tools.json` 当前有 18 项登记；orchestrator 尚未真正通过统一 registry 调用完整工具链。
- 当前不是监督学习模型系统；没有训练代码或在线自改规则。`LABEL-LEARNING-v3-20260816` 是当前学习 Challenger，`editing-policy-guards-v1` 已接未来新 run，只能自动保护已知误报或升级人审；`autocut_policy` 仍为 `NOT_APPROVED`。
- 学习驱动器硬门：普通 `delivery_orchestrator start` 默认加载 `LABEL-LEARNING-v3-20260816`，在候选冻结前后生成带目标 `run_identity`/`input_manifest` 的机器建议侧车；任何新标签回测或 shadow 都必须通过 `label_learning_driver.py evidence` 的目标包 before/after 哈希比较。旧报告没有当前代码 SHA 或冻结包哈希时，只能作历史证据。

具体状态以《当前项目进度》为准，本文件不复制逐项历史。

## 必须保持的边界

1. `<PROJECT_ROOT>/mentor的成果/` 只读，不能改写为我们的成果。
2. 原始音频、Champion、正式成片和已哈希历史运行产物只读。
3. 真实音频、转写、候选和内部资料默认只在本地处理。
4. 语义删剪必须真人明确批准；Agent 不得自批准、超时批准或默认全接受。
5. EDL 使用整数 sample，批准区间同步应用于全部语音轨。
6. Challenger 不得直接覆盖 Champion；必须冻结 benchmark、独立复核、人工晋升并可回滚。
7. 新外部工具先审来源、版本、SHA、代码/权重许可证、依赖、遥测、网络和数据流。
8. 不执行 `curl | sh`、不透明 `inference.sh`，不覆盖系统 Python，不默认上传真实素材。

## 文档更新规则

- 新产品或架构决定 → 更新 `统筹全局/全局统筹记忆.md`。
- 当前状态变化 → 更新 `统筹全局/当前项目进度.md`。
- 功能契约或结论变化 → 更新对应 `功能说明/Fxx-*.md`。
- 命令、测试、失败、SHA 和单期产物 → 写对应 run/Challenger。
- 不再创建逐会话长篇上下文压缩；`与AI的上下文/` 顶层只保留当前整体摘要。

## 交付一致性

向用户汇报时必须区分：静态代码存在、自动测试、真实音频运行、真人审核、整片发布验收。每次同时说明做了什么、没做什么、证据在哪里、结论属于事实/方向/假设、下一步完成门是什么。

没有实际运行的脚本不能称为已验证，没有逐项人工审核的 EDL 不能称为正式审核版，没有整片听审与规格确认的音频不能称为可发布成片。
