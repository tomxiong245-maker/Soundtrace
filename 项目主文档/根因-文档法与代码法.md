# 历史问题根因 · 文档法 vs 代码法

> **12+ 个 bug 的共同答案**。理解这一件事 · 未来所有类似 bug 都能提前识别 · 提前防御。
>
> 本文件不是新规则 · 是**把 CLAUDE.md 已经埋着的"已进代码强制"章节抽出来** · 让新 agent 一眼看到项目的"防御体系哪里硬 · 哪里软"。

---

## 一 · 一件事

所有踩过的坑 · 归到最后只有一件事：

> **规则写在文档里 · 代码不强制 · agent 靠"自觉"执行 · 而 agent 每次都从零开始 · 不查历史。**

或者更短：

> **文档法 vs 代码法**。

具体说：CLAUDE.md 22 条硬边界里 · **只有 6 条是代码法**（fail-closed · 缺就崩）· **其余 16 条是文档法**（agent 读了自觉遵守）。

**所有 bug 都发生在文档法覆盖的地方**。

## 四 · 为什么 §12 speaker_role_gate 没被绕过

它是**唯一一条真正 fail-closed 的规则**：

```python
if not speaker_map.exists():
    raise SystemExit("缺 speaker_map")  # 崩 · 不 fallback
```

**没有 silent fallback** —— 缺就崩 · agent 想绕也绕不过。

其他 90% 的规则都是"agent 应该 XXX" · agent 忘了就绕过 · 系统不知道 · 用户下次听审时才发现。

## 五 · 未来落地测试（新规则活得下去的唯一标准）

**任何新规则落地前 · 必须回答一句话**：

> **"如果 agent 不遵守 · 代码会不会崩？"**
>
> - 答"会崩" → OK · 这条规则活得下去
> - 答"不会崩 · 只是文档写着" → **这条规则等于不存在** · 未来一定被绕过

## 六 · 治理方向 · 从文档法迁移到代码法

**不是要用户选路径 · 是给未来 agent 一个方向**。已识别 3 个最优先要迁移的：

### 优先级 1 · Stage 前置门（治"null 传播 · MFA 类误诊"）

**病症**：Stage 3.4 出 all_candidates.json 有 null · Stage 3.5 MFA 拿到 null 无声早退 · 报告说"词典问题"（表象层归因）。

**代码法方案**：每个 stage 加前置 schema 校验门 · 缺字段 SystemExit · 参考 §12 fail-closed 范式。

**落地位置**：`稳定生产/challengers/e2e-auto-runner-v1/scripts/run_end_to_end.py` · 每个 stage 入口前加 `_validate_stage_input_schema(...)`。

### 优先级 2 · cut-verify 挂主 pipeline（治"侧车过夜"）

**病症**：cut-verify 2026-08-19 落地 · 但 `run_end_to_end.py` 不自动调 · 昨晚跑了今天忘。

**代码法方案**：把 verify_cut_plan.py 挂进 run_end_to_end.py Stage 3.7 · 未跑就 SystemExit。

**落地位置**：`skills/cut-verify/2026-08-19-0040-cut-verify-landing-and-EP04-delivery.md` P2 backlog（原文明记为"未落地"）。

### 优先级 3 · 参数 generator（治"cut_parameters 3 副本 drift"）

**病症**：20 参数值在 `cut_parameters.json` + `SKILL §7` + 落地报告 3 处副本 · 手工同步 · 忘就 drift。

**代码法方案**：`cut_parameters.json` 是唯一手改点 · 写一个 generator 从它生成 `SKILL §7` 参数镜像 · 加 CI hash 校验：手改 SKILL §7 → verify.sh FAIL。

**落地位置**：新写 `verify/scripts/render_skill_params_from_cut_parameters.py` + `verify.sh` Layer 22。

## 八 · 一句话根治哲学

> **文档能表达意图 · 但只有代码能保证执行**。
>
> 项目未来每一条规则 · 要么迁移到代码强制 · 要么明标"这是文档法 · 未来会被绕过 · 请提前警觉"。
>
> **不允许出现"看起来强制但实际靠自觉"的规则** —— 这类规则最危险 · 因为它让用户误以为系统在防御 · 实际系统不在。
