# 剪辑核心 · 3 问与 20 参数

> **新 agent 打开这个交付文档 · 先读这份**。3 分钟看懂"整套系统在干什么"。
>
> 本文件只做"用户视角的核心讲解" · 不是新规则 · 参数值以 `knowledge/cut_parameters.json` + `新skill/cut-verify/SKILL.md §7` 为权威源。

---

## 一 · 一句话核心

**整个系统只回答一件事**：

> **一个候选（比如"呃"字）到底剪不剪 · 剪的话在哪切 · 切完怎么拼。**

其他所有 skill / tool / adapter / gate / check · 都是**围着这 3 个问题**转的辅助设施。

---

## 二 · 3 问决策链（用 C007 "呃" 走一遍）

EP04 里 354.08 秒有个"呃"字（C007）· 从 raw 音频到进入最终 mp3 · 走了这条路：

```
raw 音频里有个"呃"
    │
    ├── 问题 1 · 剪不剪？
    │      · 是真口癖？还是内容？
    │      · Whisper 对它有多自信（≥ 0.6 才算真的存在）？
    │      · 主持人 backchannel 吗？（是 → 不剪）
    │      · session_feedback 里有 never_cut 吗？（有 → 跳过）
    │      · 是量词/代词吗？（是 → 不剪 · 未落地）
    │      → 答"剪"（用户 override 了 0.6 阈值）
    │
    ├── 问题 2 · 在哪切？
    │      · 用 ASR 词完整边界（rule 66 · v04 主用）？
    │      · 还是 MFA 音素边界（更精 · fallback · 未激活）？
    │      · 会不会吃前一个字尾巴？→ 相邻词保护 20ms
    │      · 会不会吃后一个字辅音起音？→ librosa onset 保护 30ms
    │      → 用 ASR 词 · 353.4 → 354.5 · 680ms
    │
    └── 问题 3 · 怎么拼？
           · 剪口在哪种区域？
             - 全在静音 → 直接对接 0ms（butt splice）
             - 跨静音-内容边界 → 短交叉 50ms
             - 在内容里 → 人审 · 长交叉 100ms
           · 剪完节奏 OK 吗？（前后词间隙 [120, 450] ms 才 OK）
           → 用 50ms 边界过渡 · gap = 294ms ✓
```

**这 3 问答对了 · 剪出来干净**；答错了就是"剪辑痕迹重"、"吃辅音"、"抢话"、"拖沓"这些坑。

## 三 · 20 参数 · 4 类分工地图

20 参数按"用户视角"分 4 类（**不是** Check 1/2/3/4 · 是"在回答哪一问"）：

### A · 决定"要不要剪"（5 个）

| 参数 | 值 | 一句话 |
|---|---|---|
| Whisper 置信度阈值 | **0.6** | ASR 自信度 < 0.6 → 判幻觉 · 不剪 |
| 候选类型白名单 | filler_hesitation · immediate_repetition | 只有这两类走幻觉检查 |
| speaker_role_gate | fail-closed | 主持人 backchannel（"嗯/对"）→ 不剪 |
| session_feedback never_cut | 查历史反馈 | 用户以前说过不剪 → 直接跳过 |
| 内容词白名单 | **backlog · 未落地** | "一些"这类量词不当口癖剪（C039 事件） |

### B · 决定"在哪切"（7 个）

| 参数 | 值 | 一句话 |
|---|---|---|
| ASR 词完整边界 | rule 66 · v04 主用 | 用整个词的 start/end 当剪口 |
| MFA 音素边界 | fallback · 未激活 | 精修边界 · 比 ASR 精 100-150ms |
| 相邻词保护 | **20ms** | 剪口不能吃前后邻词 |
| librosa onset 保护 | **30ms** | 剪口尾巴不能吃辅音起音 |
| 中心匹配容差 | 0.05s | 找 ASR 词时的时间窗 |
| 覆盖判断 slack | 0.02s | 允许 ASR 词略小于候选也算覆盖 |
| 头/尾 pad | MFA 版待定 | 精修后加多少 buffer |

### C · 决定"怎么拼"（5 个）

| 参数 | 值 | 一句话 |
|---|---|---|
| butt splice | **0ms** | 剪口全在静音 → 直接对接 · 无痕 |
| 边界过渡 | **50ms** | 剪口跨静音-内容边界 → 短交叉（v04 主用） |
| 内容区人审 | **100ms** | 剪口在内容里 → 要人审 · 长交叉 |
| fallback | 50ms | 兜底默认 |
| room tone 垫 | 10ms | butt splice 时补一小段室内噪声 |

### D · 决定"节奏 OK 吗 / 什么时候别剪"（3 个）

| 参数 | 值 | 一句话 |
|---|---|---|
| post_cut_gap 目标 | **[120, 450] ms** | 剪完前后词的空隙 · 太紧抢话 · 太松拖沓 |
| hard_reject | **< 50ms** | 剪完 gap 太紧 → 硬拒 |
| 静音探测标尺 | -40dB / 100ms / 1.5s 窗 | pydub 判"哪里是静音"的标尺 |

**总计 20 个参数 · 全部值以 `knowledge/cut_parameters.json` 为准**。

## 七 · 常见误解澄清

| 误解 | 事实 |
|---|---|
| "20 参数是 Check 1/2/3/4 的" | 20 参数是**回答 3 问的具体标尺**。Check 1/2/3/4 是 cut-verify 内部实现细节 · 不是用户视角。 |
| "剪辑核心是 pipeline 11 stage" | 不是。11 stage 是**执行工程** · 核心是 3 问决策。同一个候选每 stage 都在服务 3 问中的一个 · 换 stage 只是换视角。 |
| "cut-verify 决定要不要剪" | 只决定**部分要不要剪**（Check 1 幻觉）· 主要负责"怎么拼"和"节奏 OK 吗"。要不要剪还有 speaker_role_gate / session_feedback / autocut 7 门共同决定。 |
| "20 参数改一个另外 19 个会崩" | 参数间**基本独立** · 除 gap target_range 和 hard_reject 有单调关系（min ≥ hard_reject）· 其余独立可调。 |
