# 端到端剪辑 benchmark v1

## 核心问题

对同一份原始 N 轨节目，系统的新版本能否在不增加误删风险的前提下，让最终成片更接近人工最终版？

```text
raw N-track WAV（只读）
        ↓ 系统版本 / Skill / 规则冻结
候选 → 真人审核 → approved EDL → 系统成片
        ↓
人工最终成片 + 可选人工 EDL + 整片盲听 + 工时比较
```

## 为什么不只比 EDL

人工最终版通常还包含降噪、混音、crossfade、响度和音乐；如果只用最终 MP3，很难无歧义地反推出每一个人工剪口。因此：

- 有人工 EDL：作为最高价值的诊断真值；
- 无人工 EDL：允许通过对齐生成 `human_edit_map`，但它只作辅助；
- 无论是否有 EDL：最终仍需整片盲听与人工内容检查。

## 每期 manifest 最少需要

1. 原始所有轨道路径、SHA、采样率和 sample timeline；
2. 人工最终成片路径、SHA、规格；
3. 可选的人工 EDL 或 human_edit_map；
4. 系统版本、Skill、规则、Tool/模型和输入计划；
5. 系统候选、人工决定、系统 EDL、系统成片与 QC；
6. 盲听结论、语义误删、剪口问题。

## 集合划分

| 集合 | 用途 | 是否允许据此调规则 |
| --- | --- | --- |
| `development` | 施工、诊断、修复错误 | 可以 |
| `frozen` | 最终比较 Champion 与 Challenger | 不可以 |

首批不要急于冻结。先收齐至少若干期 raw 与人工最终版，确认样本覆盖干净录音、串音、多人、不同讲话节奏后，再固定一部分作为 `frozen`。

## 不可接受的结论

- “系统波形和人工 MP3 相似，所以语义剪对了”；
- “候选被接受率高，所以召回高”；
- “开发集变好，所以可以进生产”；
- “没有人工 EDL，就可以让模型自己猜并直接发布”。

## 文件模板

- `episode.manifest.template.json`：每期输入/参考/输出的可追溯索引；
- `system-report.template.json`：一次 Challenger 对该期的结果；
- `NO_CANDIDATE_AUDIT_README.md`：从冻结 run 的无候选区域生成固定随机、无媒体读取的人工漏检抽查窗口；

不复制真实音频到本目录。所有实际音频保持原位置，并由 SHA 绑定。
