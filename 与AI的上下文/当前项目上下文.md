# 当前项目上下文

> 更新时间：2026-08-12（EP04 真人审核与技术渲染已完成；Tool 总控 Challenger 已完成合成 fixture 验证）  
> 用途：给新 AI 对话快速建立整体认识。它不是运行日志；所有详细状态以链接的权威文档和真实产物为准。

## 项目是什么

明略多轨播客剪辑助手：本地运行、可追溯，由机器完成检查、转写、候选和确定性音频处理，由真人决定所有语义删剪与最终听感。旧样例以双轨为主，当前输入契约已泛化为任意 N 条对齐 mono 轨，重点是三轨。

```text
N 轨 WAV
→ 检查/同步/降噪/ASR/说话活动
→ 候选与 A/B
→ 真人 accept/reject（`adjust` 以后再恢复）
→ approved EDL
→ 同步剪切/混音/授权音乐/QC
→ WAV/MP3 + feedback bundle
```

目标指标：整片可发布 + 剪辑质量（**2026-08-17 起**，"审核/返工/维护时间与净节省时间"已按项目负责人明确指令从 benchmark 判据中撤除；产品愿景公式在《产品要求与验收标准》§1 保留作为方向叙述，但不再作为完成门）。

## 当前最短路径

1. 对 EP04 去重技术试听版整片听审，复核 6 个剪口和未提候选区域。
2. 增加主麦 automix、响度、片头片尾和发布 QC，形成发布候选。
3. 收 Claude 的串音、瞬态事件、说错重来 Challenger 证据，再由真人审核；`adjust` 暂不做。
4. 并行补 12 段人工 gold、多引擎 verdict 和净节省时间。
5. 用经验沉淀 Skill 持续总结案例，多期有效数据后再做内部经验学习与 Loop。

## 监督学习口径

当前不是监督学习。现状是规则候选 + 二态人工决定 + 版本化留痕；没有 model/loss/training。

P0 让输入可信，P1 让人工标签可信；当前先用 `accept/reject` 做案例检索和 Skill/规则总结，未来才可能训练候选排序器。生产中禁止在线自我修改，新版只能 Challenger → 冻结 benchmark → 独立复核 → 人工晋升 → Champion。

## 永久边界

- 原始素材、Mentor 成果、Champion 和已哈希历史产物只读。
- 真实音频、转写和内部资料默认不离开本机。
- 所有语义删剪必须真人明确批准。
- EDL 使用整数 sample 并同步作用全部语音轨。
- 新工具先审许可证、版本、SHA、依赖、遥测和数据流，再进入隔离 Challenger。
- 不得把静态代码、fixture、bulk accept 或状态机演示表述为真实产品完成。
