- self-correction-v1 challenger **已经存在**（8/8 单元测试过），本轮只做两件事：
  1. **在真实 EP04 数据上跑一次 detection**（此前从未跑过）
  2. **登记到 `main/tools/tools.json` 让 tool_lookup 能查到**（tools 从 30 项 → 31 项）[HIGH]

  - `gap_out = 353`（句间停顿 > 2.5s，是正常对话切换/思考停顿）
  - `too_long = 193`（句子 > 12 字，正常长句）
  - `no_prefix = 141`（不共享前缀 = 换话题）
  - `passed = 0`
- 契约测试：P1 3/3 · P2 12/12 · sync check PASS · `tool_lookup.verify_manifest()` no errors。[HIGH]

## 判断（[MED]）

- 现有 detection 的算法假设是"**停顿 ≥ 0.6s 切开的两个整句 A、B**，判 B 是不是 A 的改写"。EP04 的说错重来实际主要是**半句内快速自我修正**（gap < 100 ms 根本没触发切句），detection 抓不到。[HIGH]
- Debug 时临时把 `max_abandoned_chars` 放宽到 25 也没抓到 —— 说明**问题不是阈值，是算法层的抽象跟内容不匹配**。已回退 rules。[HIGH]
- policy v2 白名单里 self_correction 保留：**当前 detection 不产出，等于空转但无副作用**。等重新设计 detection 后再评估。[MED]
- **重设计方向**：不是"句对"，而是"词级 self-repair pattern" —— 半句内检测"字面重复+改写"（比如 `X → X'`, 其中 X 和 X' 共享 ≥ 1 字 + `edit_ratio ≥ 0.5` + `gap < 300ms`）。这本质上会和 immediate_repetition 的检测框架融合。[MED]

## 建议 · 后续动作（[MED]）

1. **接受当前状态**：detection 已登记，policy 白名单已开，物理层 0 命中不阻塞流程。EP05 上线时用同一 detection 直接跑，如果新节目风格不同（有明显停顿+重说）可能命中。
